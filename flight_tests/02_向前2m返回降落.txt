测试 2：起飞 1 m，向前 2 m，返回起点并降落

适用：NX / Ubuntu 20.04 / ROS Noetic / PX4 + MAVROS。
程序目录：/home/l1/outdoor_offboard_tests/。无需 catkin 编译。
每个新终端首先执行：

source ~/outdoor_offboard_tests/env.sh

坐标与高度
- 原点是本次程序启动时记录的飞机当前位置，不是强制 local=(0,0,0)。
- “向前”按起飞前机头在 MAVROS local ENU 中的偏航计算。
- MAVROS 的 local x/y 是局部 ENU 坐标，不能把 local x 永久理解成机头前方。
- 1 m 为融合位姿 z 相对起点增加 1 m，不是激光测距保证的真实离地高度。
- 位置参考和速度前馈均平滑变化，起降爬升参考速度上限 0.35 m/s。
- 不修改飞控 EKF、解锁检查、失联保护或速度参数。不会自动强制上锁。

起飞前清单（每一项都确认）
[ ] 选择平坦空旷场地，2 m 往返路线以及周围有足够余量，没有人员和障碍。
[ ] 飞机、电池、桨叶、相机及线缆固定可靠，电池电量足够。
[ ] 遥控器能接管，操作者知道如何切回 Position/Land，并观察飞机实际高度。
[ ] 先确认手动 Position 模式能正常定点；明显漂移、慢慢下降时不要继续自动测试。
[ ] MAVROS connected=True，飞前 armed=False，extended_state 的 landed_state=1。
[ ] local pose/velocity 持续更新，飞机静止时位姿已稳定，无明显跳变。
[ ] 室外检查 GPS fix_type、卫星数及精度，定位未稳定时先等待。
[ ] 没有其他起飞脚本、视觉控制器、px4ctrl 或 ego_to_mavros 同时发布设定点。
[ ] 依次完成测试 1、测试 2，再执行测试 3；上一项异常先处理。

关闭旧程序（仅地面未解锁时操作）
在原终端按 Ctrl+C 关闭旧 EGO/控制脚本。后台启动的旧 EGO 可执行：

pkill -INT -f '[/]opt/ros/noetic/bin/roslaunch /home/l1/ego_d435i.launch'

检查控制话题发布者：

rostopic info /mavros/setpoint_raw/local
rostopic info /mavros/setpoint_position/local
rosnode list

EGO 旧 launch 内有 ego_to_mavros 桥接节点，本套测试禁止与其同时运行。
程序会检查多个设定点发布者，发现冲突会拒绝起飞，而不是争抢控制。
节点已退出但仍显示旧注册信息时，先运行 rosnode cleanup，核对要清理的是离线节点。

终端 A：MAVROS（已经运行就复用，不要重复启动）

source ~/outdoor_offboard_tests/env.sh
roslaunch mavros px4.launch fcu_url:=serial:///dev/ttyACM0:921600

MAVROS 会在需要时启动 roscore，无需重复运行 roscore。
若飞控设备名变化，先 ls -l /dev/serial/by-id/，再按实际设备修改 fcu_url。

终端 B：飞前基础检查（每条查看后 Ctrl+C，或另开终端）

source ~/outdoor_offboard_tests/env.sh
rostopic echo -n 1 /mavros/state
rostopic echo -n 1 /mavros/extended_state
rostopic echo -n 1 /mavros/local_position/pose
rostopic echo -n 1 /mavros/local_position/velocity_local
rostopic echo -n 1 /mavros/battery
rostopic echo -n 1 /mavros/gpsstatus/gps1/raw

频率检查：

rostopic hz /mavros/local_position/pose

注意电池电压 0 或 percentage=-0.01 等表示数据不可用，不能当成电量正常。
GPS 的 h_acc/v_acc 若可用按 MAVLink 字段单位理解，不与气压高度直接混算。


任务顺序
记录当前位置和初始机头方向 -> OFFBOARD 起飞 1 m -> 稳定 2 s ->
沿初始机头方向前进 2 m -> 稳定 2 s -> 返回起点上方 1 m -> 稳定 2 s -> 降落。
水平参考速度最大 1 m/s，加速度最大 0.5 m/s²；短距离会平滑加减速，不是瞬间冲到 1 m/s。
全程保持初始偏航，返航是沿已检查的空旷路线倒退飞行。
此项是直接跟踪平滑位置/速度参考，不含避障。
相机、EGO、点云转换程序都不需要启动。

启动本项测试（在新的任务终端执行）

source ~/outdoor_offboard_tests/env.sh

# 第一步：只做预检查，不解锁、不起飞
/usr/bin/python3 ~/outdoor_offboard_tests/test2_forward_return.py

# 看到 PREFLIGHT_OK 和 NO_ARM_NO_FLIGHT 后，确认现场可以起飞，再执行：
/usr/bin/python3 ~/outdoor_offboard_tests/test2_forward_return.py --execute

第二条带 --execute 的命令会自动切 OFFBOARD、解锁并完成全部飞行流程。
运行中不用再手动调用解锁服务，也不要启动其他起飞脚本。
预检查通过后，实际执行时仍会重新检查状态并重新记录起点。


实时观察（各命令可单独开一个终端）

source ~/outdoor_offboard_tests/env.sh
rostopic echo /outdoor_test/status

# 飞控模式与解锁状态
rostopic echo /mavros/state

# 飞控实际融合位姿（绝对 local 坐标）
rostopic echo /mavros/local_position/pose

# 实际速度，关注 twist.linear 的 x/y/z
rostopic echo /mavros/local_position/velocity_local

# 故障原因，如 No offboard signal、定位异常、解锁拒绝等
rostopic echo /mavros/statustext/recv

# 本程序的 MAVROS 设定点应约 30 Hz
rostopic hz /mavros/setpoint_raw/local

手动中止
- 测试程序终端按 Ctrl+C：请求结束本次任务并 AUTO.LAND，不是立即切断设定点。
- 或另开已加载环境的终端执行：

rosservice call /outdoor_test/land '{}'

- 此服务会在当前位置降落，不保证先返回起点；异常时优先遥控器接管。
- 遥控器/PX4 已经切离 OFFBOARD 时，程序停止争夺控制，不自动切回或重新解锁。
- 飞行中不要用 kill -9，也不要关闭 MAVROS/拔串口来停止任务。
- 只有看到 AUTO.LAND 确认后才停止 OFFBOARD 悬停设定点；等待 landed_state=1 且 armed=False。

自动保护与限制
- 规划指令或位姿超时、目标长时间未到、参考跳变、控制冲突均报告失败。
- 本地位姿相对起点水平半径超过 5 m，或高度超出 -0.5～1.8 m，触发失败降落。
- 实测总速度大于 1.35 m/s 持续 0.5 s，触发失败降落。
- 参考速度上限不等于真实空速/地速绝对不会超调，仍需观察实测速率并遥控接管。
- AUTO.LAND 被拒且飞机仍在 OFFBOARD 时，程序保持悬停设定点并提示接管。
- 坐标估计漂移无法靠这个状态机消除，报告中的误差均为估计坐标内误差。

保存的数据
- 每次运行自动创建 ~/outdoor_offboard_tests/logs/testN_日期时间_编号/。
- report.json：任务成功/失败、阶段事件、起点/目标、最大参考与实测速度、解锁至结束耗时。
- samples.csv：约 10 Hz 保存 local 位姿、相对高度、速度与设定点。
- /outdoor_test/path：实际融合位姿轨迹，可在 RViz 添加 Path 显示，Fixed Frame 设为 map。
- 不带 --execute 的运行只检查，不发送飞控设定点、不切模式、不解锁。
- TEST_PASSED 表示程序判据通过，实际飞行效果仍由现场观察确认。

代码验证范围
本套交付进行语法、数学限速与旧轨迹过滤检查，以及 NX 上不解锁预检查。
这些不能替代实机飞行验证；没有提前替你们执行任何起飞。

https://docs.px4.io/main/en/ros/mavros_offboard_python
本程序使用 30 Hz 设定点；PX4 要求持续的 OFFBOARD 设定点数据流。

本项通过判据
前进方向正确；到前方约 2 m 后返回起点上方；速度平稳；落地上锁。
终端应最终出现 TEST_PASSED；中间出现 TEST_FAILED/PILOT_TAKEOVER 不能视为通过。
